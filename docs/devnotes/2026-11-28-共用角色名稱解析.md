# 2026-11-28　pools.js 提供共用的角色名稱解析

## 改了什麼
`pools.js` 新增並匯出（瀏覽器是 `window.CharacterPools.*`）：
- `CHARACTER_NOTE_TAGS = ['同族', '戰型', '擊種', '雙削']`
- `splitCharacterName(name) → { base, suffix }`：suffix 是結尾的「-數字」加上可選的「(註記)」（半形、全形括號都收，前面可以有空白），兩個都 trim。
- `baseCharacterName(name) → string`：拿掉編號與註記。
- `fixCharacterName(fixes, name) → string`：`fixes` 是 `readNameFixes()` 的結果；用 `resolveName` 解析 base，新名稱的空白拿掉，再接回 suffix；沒有修正或繞回自己時原樣回傳。
既有函式與 `pools.json` 格式沒動。測試 +3（tests/pools.test.js）。

## 為什麼
優化 #8：同一套規則原本在 gacha `notes.js`、`script.js` 和 fruit-assign `script.js` 各有一份副本，改一處容易漏。之後這三處改呼叫這裡（由主對話改）。

## 怎麼用
```js
const P = window.CharacterPools;            // Node：require('pools.js')
const fixes = P.readNameFixes(sharedCharactersDoc);
P.fixCharacterName(fixes, '砲姐-2(擊種)');   // →「御坂美琴-2(擊種)」
P.baseCharacterName('虹夏-2(雙削)');         // →「虹夏」
```

## 已知限制
- 名稱本身以「-數字」結尾的角色（c0910「P-47」）會被拆成「P」＋「-47」，和舊副本一樣。要修正這種名稱的寫法時會對不到。
- 沒有修正時原樣回傳（名稱裡的空白也不動）。果實分配舊的 `fixGachaName` 在沒有修正時會把名稱裡的空白拿掉，改用新函式後這點會不同。
