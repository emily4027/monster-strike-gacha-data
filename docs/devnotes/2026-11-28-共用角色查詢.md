# 2026-11-28　1.5.0 共用的角色查詢

## 改了什麼
- `pools.js`：新增 `buildCharacterIndex(roster, { fixes } = {})`、`lookupCharacter(index, name)`，並匯出（瀏覽器 `window.CharacterPools`、Node `require('./pools.js')`）。
  - 索引：名冊每隻有 id 的角色的名稱、別名、形態名稱 → `{ id, name, element, kind }`（沒有的欄位是空字串）。
  - 查詢：`baseCharacterName` → `resolveName(fixes, …)` → `poolKey` 比對；修正後的名稱查不到時再用原名查一次。查不到、空字串、index 不對時回傳 `null`。
- `js/common.js` 的 `loadElementClasses`：直接比對不到時，用 `lookupCharacter` 再找一次。
- 測試 +2（136 個）：查得到（名稱、別名、形態、同名編號、註記）、查不到（名冊外、沒編號、空的）、名稱修正後才查得到、同名不同版本；實際的 `characters.json` 每個名稱都查得回自己。

## 為什麼
- 使用者選「B 精簡版」（見 `2026-11-28-共用名冊評估.md`）：存檔照舊存名稱，名冊以外的角色不連結。

## 怎麼用
```js
const index = CharacterPools.buildCharacterIndex(roster, { fixes: CharacterPools.readNameFixes(sharedCharactersDoc) });
const c = CharacterPools.lookupCharacter(index, '惠比壽-2');   // { id: 'c0xxx', name: '惠比壽', element: '…', kind: '…' } 或 null
```

## 已知限制
- 同名不同版本只用名稱分不出來。
- `poolAliases`（只在某個卡池才算的寫法）不比對。
- 名稱本身帶「-數字」的會被當成同名編號。
- 網頁上色的改動沒有在瀏覽器實測。
