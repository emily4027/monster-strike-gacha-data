# 2026-11-28　改用工具箱共用 firebase.js、shared.js（優化 #7）

## 改了什麼
- `js/firebase.js`：刪掉 config 和 initializeApp，改 `import { app, auth } from '/monster-strike-toolbox/shared/firebase.js'`；Firestore 自己 `getFirestore(app)`。掛在 window 的名稱（firebaseAuth、db、envAppId、firebaseFns）不變。
- `index.html`、`characters.html`：在 `js/common.js` 前面載入 `/monster-strike-toolbox/shared/shared.js`（defer，順序在 common.js 之前）。
- `js/common.js`：
  - 選單改呼叫 `MSShared.loadToolboxMenu('gacha-data', { fallbackTool: THIS_TOOL })`，刪掉 `TOOLBOX_TOOLS_URL` 和自己的 renderToolboxMenu。
  - `waitForFirebase` 改用 `MSShared.waitFor`（100ms、5 秒，和原本一樣）。
  - Firestore 路徑改用 `PATHS.sharedEvents`、`sharedRoster`、`sharedCharacters`、`admin(uid)`、`gachaRecords(envAppId, uid)`。
- scraper/（Node、admin SDK）沒動。

## 為什麼
五個工具的 Firebase 設定、選單、路徑只留一份，改一處各工具跟著用。

## 怎麼用
不用做什麼；本機要從 Monster-Strike 根目錄開伺服器（例如 http://localhost:8001/monster-strike-gacha-data/），根相對路徑 `/monster-strike-toolbox/...` 才讀得到。

## 已知限制
- `shared.js` 沒載入時，common.js 用內建的一份路徑（和 PATHS 結果相同），等於還留一份副本當備援。
- `shared/firebase.js` 讀不到時，整個 firebase.js module 載入失敗，行為和原本 SDK 載不到一樣：等 5 秒後顯示離線、改用 events.json。
- 沒有實際登入驗證。
