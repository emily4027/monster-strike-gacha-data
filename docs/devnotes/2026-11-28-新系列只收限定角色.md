# 2026-11-28　1.1.0 新系列轉蛋只收限定角色

## 改了什麼
- `scraper/pool-parse.js`：
  - `parseHeadingLists` 多存 `fulls`（各名稱的獸神化後全名）。
  - `extractPoolData` 走小標題路徑時也跑 `periodSections`（新函式 `withPeriodSections`，記成 `specials`、補屬性）。
  - 新增 `headingListLimited`：名稱或全名有 α、在 specials 裡、名冊 kind 是 period／limited 才留；kind 是 regular 一律拿掉。
  - `planHonke` 在選好名單之後、推測名稱提醒之前過濾 fromHeadings 名單，拿掉的出 flag；全空就不變動。
- `scraper/apply-pools.js`：把名冊 kind 做成 `overrides.kinds`（`{ poolKey(名稱、別名、形態): kind }`）傳進 `planPoolChanges`。
- 資料：刪 `pools.json` 的「銀河冒險 II」與 names 的 c0404～c0406；`characters.json` 這 3 隻加 `kind: 'regular'`。
- 測試 +4（129 個）。

## 為什麼
- 使用者回報新系列常駐角色被收成限定卡池。公告格式分不出季節限定和常駐，使用者提供規則：新系列裡有 α 的必定限定、其他大概率常駐，並注意世足激獸神那種沒有 α 的期間限定特別造型。設計由 Fable 子代理分析（現有資料零誤判）。

## 怎麼用
- 自動。例外在角色頁改類別：常駐標成期間限定就會收，期間限定標成常駐就不收。

## 已知限制
- 只作用在小標題名單路徑；祭典表格、合作路徑不變。
- 之前存下的公告資料沒有 `fulls` 時只看獸神化前名稱。
- 被當成常駐的角色不會自動編進名冊；這期卡池要手動加回時用角色頁「出自卡池」。
- 行事曆管理員視角對「有公告網址但沒有卡池」的活動會提示「爬蟲下次執行時會讀」，對已讀過的公告是誤導（舊行為，沒改）。
