# 2026-11-28　1.0.1 爬蟲推送重試、孤兒編號

## 改了什麼
- `.github/workflows/scrape.yml`：scrape job 四個 `git push` 前加 `git pull --rebase --autostash --quiet origin main`。
- `roster.js` `foldEdits`：卡池裡名冊沒有的編號不再丟錯；用 `poolsData.names[id]` 找名冊裡同名（含別名、形態）的角色換過去，找不到就拿掉；回傳 `orphans: [{ pool, month, id, name, into }]`。
- `scraper/fold-roster.js`：每個 orphan 印一行 `::warning::`。
- `roster.js` `poolsToNames(poolsData, data, onOrphan)`：名冊沒有的編號改用 `names` 的原本名稱並呼叫 `onOrphan`；`names` 也沒有才丟錯。`apply-pools.js` 把它變成卡池 PR 報告的 flag。
- `roster.js` `poolsToIds`：同一期卡池重複的編號只留一個（孤兒換回併進去的那隻時會重複）。
- 測試 +2（125 個）。

## 為什麼
- 主對話上線後審查：Action 執行中有人 push 會整步失敗；卡池 PR 和 main 的合併角色交錯時，fold 每天報錯。

## 怎麼用
- 自動。看 Actions 執行結果的黃色警告，被拿掉的到角色頁「出自卡池」加回。

## 已知限制
- `pools.json` 的 `names` 沒記到的孤兒編號，卡池 PR 那邊仍會丟錯（`names` 是每次寫 `pools.json` 時一起產生的，正常不會缺）。
- 被拿掉的角色不會自動補回；只能靠警告讓管理員處理。
- `git pull --rebase` 遇到真的衝突（同一個檔被兩邊改）仍會失敗，這是刻意的。
